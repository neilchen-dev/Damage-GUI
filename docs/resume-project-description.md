## 中文简历 4 条 bullet

- 基于 Python 开发二维毁伤场快速预测系统（Tkinter 桌面端 + CLI），采用分层模块化架构（界面 / 应用服务 / 算法核心 / 存储四层），实现质心对齐 RBF 与 POD-RBF 降阶代理模型，将 473×473 高维毁伤场预测压缩至毫秒级，并通过结构化交叉验证（整层留出 / 角落外推）与 OOD 可信度检测保证预测可靠性。
- 设计模型全生命周期可追溯机制：每次训练自动产出模型元数据（UUID、训练数据 SHA-256 指纹、Git commit、训练参数与验证指标），采用软件版本 / 元数据 schema / 模型格式三版本号分离策略，joblib 与 JSON sidecar 双写互验，旧版模型向后兼容可加载。
- 基于 SQLite 建立训练与批量预测任务追溯库（models / jobs / prediction_results 三表模型与索引设计），实现后台任务状态机（PENDING/RUNNING/SUCCESS/FAILED/CANCELLED 显式转移）与 CSV 批量预测（行级失败隔离、协作式取消保留部分结果）；数据库故障时计算继续但以 ERROR 日志与界面警告显式降级，不静默丢失追溯。
- 建设自动化质量门禁：147 个单元 / 端到端测试用例与固定种子数值回归黄金值测试（容差依据跨平台实测漂移设定），配合 GitHub Actions 实现 ruff 静态检查 → Windows/Linux 双平台测试 → Windows PyInstaller 真实构建产物校验与 artifact 上传的完整流水线，仅 tag 触发 Release 发布。

## 面试项目介绍（约 550 字）

这个项目解决的业务问题是武器效能评估中的计算瓶颈：毁伤场依赖大型仿真，单个工况要数小时，而评估需要在大量工况组合上反复查询。原始方案是一个单文件 GUI 脚本，算法和界面耦合在一起，训练时界面卡死、结果不可复现、也没有任何手段回答"这个预测是哪个版本的数据、哪个模型算出来的"。

我做的第一件事是架构重构：把单文件拆成四层——Tkinter 界面层、应用服务层、算法核心层和存储层。算法上实现了质心对齐插值解决毁伤图案随工况平移导致的插值重影，再叠加 POD 降阶，把上万维的场预测变成几十维模态系数的插值问题，预测耗时降到毫秒级。模型验证上，我没有停留在随机留出，而是实现了按高度/速度/角度整层留出和角落外推的结构化交叉验证，配合 SVD 内在维度加双层凸包的 OOD 检测，能明确告诉用户当前工况是插值还是外推、可信度多高。

工程化是第二阶段的重点。训练在后台任务状态机中执行，五种状态显式转移、可取消、防重复提交，GUI 不再直接操作线程对象。每次训练产出模型元数据——训练数据的 SHA-256 指纹、当时的 Git commit、参数与验证指标，并且用三个独立的版本号分别管理软件版本、元数据结构和模型格式，旧模型文件也能兼容加载。训练任务和批量预测结果写入 SQLite 追溯库，一条批量预测记录可以回溯到数据指纹、代码版本和验证结论；数据库故障时计算照常完成，但会以错误日志加界面警告的方式明确提示追溯缺失，而不是静默吞掉。批量预测支持 CSV 进出，单行失败不中断整批，取消时保留已完成的结果。

测试与交付上，项目有 147 个测试用例，全部基于合成数据；其中数值回归测试用固定种子的黄金值锁定预测场、POD 模态、OOD 分级和核心指标，容差是根据双进程实测漂移为零的证据设定的，没有为了通过 CI 放宽。CI 流水线是 ruff、Windows 和 Ubuntu 双平台测试、再到 Windows 上真实执行 PyInstaller 构建并校验可执行产物、上传 artifact，只有打 tag 才发布。最终这个项目可以作为一个可追溯、可批处理、可测试、可交付的工程软件系统来使用，而不是一个只能演示的算法脚本。
