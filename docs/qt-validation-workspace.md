# Phase 2.2 — Validation Workspace

Implemented on `qt-redesign`, retaining the existing workbench and numerical algorithms.

1. **Files.** New `services/validation_service.py`, `qt/validation_workflow.py`, `qt/panels/validation.py`, `scripts/capture_qt_validation.py`, `tests/test_qt_validation.py`, `tests/test_validation_service.py`, `tests/test_validation_storage_migration.py`, and this report. Updated `model/bundle.py`, `storage/db.py`, Qt workflow/main-window/history/task-adapter/i18n/theme, Prediction/Batch busy guards, the synthetic fixture's optional axis values, and navigation test expectations.
2. **Architecture.** The dark Validation workspace contains Overview, Samples, Comparison, and a single Distribution chart. A light inspector owns truth directory, mode-specific parameters, Raw/Smoothed presentation, Run/Cancel, and JSON export. ValidationWorkflow drives the existing TaskManager/TaskAdapter and repositories. Truth discovery and solver compatibility checks also run in background workers. RBF and POD-RBF are supported; another scientific job prevents submission while a shared model could be used concurrently.
3. **Five modes.** The real identifiers remain `random`, `leave_h_out`, `leave_v_out`, `leave_deg_out`, and `corner`. The existing `make_splits` and `DamageModelService.train_bundle` perform splitting, fitting, prediction, and evaluation. Two optional hooks were added without changing default behavior: select an existing layer fold, and observe completed fold pairs. Layer modes can run all folds or one actual layer. Corner uses only the existing velocity/angle thresholds, not a fabricated height region. Existing random seed/test fraction are configurable. Validation assesses a refitted method/configuration; it does not benchmark immutable loaded weights or replace the loaded model.
4. **Raw/Smoothed.** The default is Raw. Switching only selects existing report values and rebuilds presentation; it does not train or recompute metrics. Numerical summaries explicitly show the actual damage scope. Sample error columns select existing Raw/smoothed fields. Spatial metrics remain Raw in both views. History restore uses the metric view captured at submission.
5. **Metric groups.** Numerical: existing R², mean relative error, P95 hybrid error, RMSE, MAE. Spatial: existing centroid/peak-position error (m), peak-intensity error, IoU and Dice. Reliability: HIGH/MEDIUM/LOW, outside global support, insufficient local support. OOD detectors are fit on each fold's training conditions through the same core detector factory; the final full-data detector is not used to make held-out results appear in-distribution. The histogram uses per-sample P95 hybrid values and the existing aggregate P95 hybrid as a labelled vertical reference; it does not calculate another percentile or invent a combined score.
6. **Sample details.** Model/view tables use 30 px rows, selection, resizable columns and individual-metric sorting. Click a row to see its condition, confidence, both error views, and spatial measures. Worst cases are chosen by sorting a real metric, including P95, centroid error, or Dice; no composite ranking is added.
7. **Comparison.** Uses the existing FieldView and render_heatmaps pipeline. Prediction occupies the main plot, truth/error the companion plots, with unchanged shared damage colormap/limits and a symmetric diverging error scale. Chinese/English scientific labels are translated by the existing renderer. Runtime arrays are retained for inspection only.
8. **Persistence.** Jobs use the business kind `validation`. Existing jobs.details_json stores model reference, mode, settings, both report views, sample/fold counts, timing, software/hash provenance and OOD summary. An exclusively-created JSON sidecar stores per-sample metrics. Validation never writes to prediction_results, and no field matrices enter SQLite or JSON. The initial audit showed jobs.kind's CHECK rejected validation; the narrowly scoped existing table-rebuild migration was extended to accept it. SQLite user_version advances to 7 without downgrading newer versions. All columns, existing IDs/results and foreign-key links are preserved. No validation result table was created.
9. **History.** All/Prediction/Batch/Validation filters share repository pagination. Validation rows show the mode and selected layer. Details show parameters, Raw/Smoothed summaries, spatial/OOD values, timing and model software/training hash. Sidecar sample metrics are read in the background and previewed up to 1,000 rows. Missing sidecars leave the job summary accessible. Historical matrices are explicitly unavailable; Restore Validation Settings fills mode/layer/seed/view without running. Summary JSON export is available from the live workspace.
10. **Cancel/failure.** Uses the existing cooperative cancellation boundaries. Completed folds observed before cancellation are retained and evaluated with the original report generator. It does not interrupt an RBF/PCA solve. FAILED jobs store a bounded error; full traceback goes to existing logs. UI terminal state follows persistence reconciliation. Database failure leaves calculation usable with an explicit tracing warning. The TaskAdapter now waits for all submitted finished events before stopping its timer, fixing a reproducible race where a quick follow-up finalizer could otherwise leave Prediction running forever. A deterministic regression covers it.
11. **Performance.** See `outputs/qt_phase22/evidence.json` for actual five-mode wall times and sample counts on a 3×3×3 shared synthetic grid. Height validation selects h=3 (9 samples); velocity/angle run all three folds (27 samples); random tests 6 samples; corner v≥300 and deg≥30 tests 3. The smaller original two-layer fixture genuinely makes velocity/angle RBF splits singular. Background compatibility probing uses the original split builder and RBF solver to disable unsupported settings rather than modifying numerical behavior. Peak memory was not measured.
12. **Screenshots.** Fourteen screenshots under `outputs/qt_phase22`: ready, running, random/height/corner complete, Raw/Smoothed, sample table, worst-case sorting, distribution, comparison English/Chinese and History English/Chinese. The evidence directory also contains `validation.sqlite` and its per-job JSON sidecars. All metrics and fields come from actual synthetic RBF execution.
13. **Tests.** Full suite: 250 passed, 1 skipped. Includes real five-mode Qt execution, selected layer, Raw/Smoothed without rerun, comparison normalization, History/restore, persisted model/mode/metrics, no validation prediction_results, RBF/POD-RBF, missing truth, failure/cancellation, preservation of a completed cancelled fold, exact report equality to the original core, old-schema migration with result references, and the fast-finalizer adapter regression. Existing Prediction, Batch, CLI, Web, Tk, and numerical tests remain in the full suite.
14. **Limits.** Validation refits fold models and may be costly on production-size data; it does not reuse the loaded model's fitted weights. The trace model ID/hash identify the submitted model/configuration; the validation truth directory can be a different dataset, and inputs are not immutable snapshots. Historical sample metrics survive in sidecars, but fields do not. Summary report export is JSON, without a new PDF/Markdown pipeline. The split builder's existing minimum/geometric constraints are retained. Compatibility probing cannot predict every later I/O or field-data failure. Abrupt process termination can still leave a nonterminal job; startup reconciliation remains future work. Native Windows/Linux GUI launching was not manually exercised in this macOS offscreen run.
15. **Phase 2.3 proposal.** Add startup reconciliation for interrupted jobs, result pagination/export from History, and a managed validation-artifact lifecycle. Consider capturing a validation-dataset digest through the existing hash helper when stronger input provenance is required. Keep Training/Aim outside this scope.

Reproduce:

```sh
QT_QPA_PLATFORM=offscreen .venv/bin/python scripts/capture_qt_validation.py
.venv/bin/python -m pytest -q
```
